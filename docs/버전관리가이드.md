# 개인 프로젝트 버전관리

TeamShop 개인 프로젝트는 기능별 브랜치와 단계별 커밋으로 변경 이력을 관리합니다.

| 브랜치 | 용도 |
| --- | --- |
| main | 실행 가능한 최종 코드와 문서 |
| feature/shop-core | 회원·상품·장바구니·주문 처리 |
| feature/shop-ui | 사용자·관리자 화면과 통합 테스트 |
| docs/project-report | 요구사항·기능·테이블·화면 설계 문서 |

## 기능 개선 절차

1. main의 최신 코드를 기준으로 작업 브랜치를 생성합니다.
2. 변경 목적에 맞게 기능을 구현하고 필요한 검사를 수행합니다.
3. `mvn test`로 통합 테스트를 실행합니다.
4. 변경 이유와 검증 내용을 커밋에 기록합니다.
5. GitHub Actions 결과를 확인하고 main에 반영합니다.
6. 구현이 달라진 부분은 설계 정의서와 시연 시나리오에도 반영합니다.

이전 커밋과 병합 이력은 유지하여 개인 프로젝트의 변경 과정을 추적합니다.
